# Data Dictionary

All data is **synthetic**, generated by `generate_dataset.py` (fixed random seed 42). No real customer, bank or loan data is used.
Amounts are in INR. The data cut-off is **31 Dec 2024**.

## Customers  (Clean_Customers.csv, 3,200 rows)
| Column | Type | Description |
|---|---|---|
| CustomerID | text, PK | `C00001` onwards |
| Age | int | 21 to 65 |
| Region | text | North, South, East, West, Central |
| EmploymentType | text | Salaried, Self-Employed, Business Owner, Retired |
| AnnualIncome | int | INR per year. Missing values were filled with the median for the employment type |
| CreditScore | int | 300 to 850. Invalid values (0 or 9999) were replaced with the median |
| JoinDate | date | Customer since |
| CreditScoreImputed | 0/1 | 1 if the score was replaced during cleaning |
| AnnualIncomeImputed | 0/1 | 1 if the income was filled during cleaning |

## Loans  (Clean_Loans.csv, 4,000 rows)
| Column | Type | Description |
|---|---|---|
| LoanID | text, PK | `L00001` onwards |
| CustomerID | text, FK | to Customers. A customer can have several loans |
| LoanType | text | Personal, Auto, Home, Education, Business |
| LoanAmount | decimal | INR disbursed |
| TenureMonths | int | 12 to 240 depending on product |
| InterestRate | decimal | Annual rate in percent, for example `11.34` |
| OriginationDate | date | Jan 2021 to Sep 2024 |
| Status | text | `Active`, `Closed` (fully repaid) or `Defaulted` |

## Payments  (Clean_Payments.csv, 87,428 rows)
One row per instalment paid, from first instalment to the data cut-off (or to the month before default).
| Column | Type | Description |
|---|---|---|
| PaymentID | text, PK | |
| LoanID | text, FK | to Loans |
| InstallmentNo | int | 1 to tenure |
| DueDate / PaidDate | date | |
| AmountDue | decimal | Scheduled EMI |
| InterestDue | decimal | Interest part of that EMI |
| AmountPaid | decimal | Less than AmountDue means a part payment |
| DaysLate | int | PaidDate minus DueDate |

## Defaults  (Clean_Defaults.csv, 321 rows)
| Column | Type | Description |
|---|---|---|
| DefaultID | text, PK | |
| LoanID | text, FK | to Loans (at most one default per loan) |
| DefaultDate | date | Due date of the first missed instalment |
| OutstandingAtDefault | decimal | Principal balance at default |
| RecoveryAmount | decimal | Amount recovered afterwards |

## How the synthetic data behaves (so findings are read correctly)
- Default probability rises as credit score falls, as loan-to-income rises, and for Personal and Business loans; it falls for Home loans.
- Interest rate is priced from loan type, credit score and tenure, plus random noise.
- Borrowers who later default are made more likely to pay late or part-pay in their last three instalments, so the
  repayment-behaviour gap in script 10 reflects that design and is not a real-world estimate.
- Recent loans have had less time to default, so newer vintages show lower default rates.
